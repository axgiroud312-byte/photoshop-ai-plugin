# 验收与本地测试计划

## 证据分层

| 状态 | 能证明什么 |
|---|---|
| 文档/目录已读 | 接口声明和已知差异 |
| Node/Mock 通过 | 纯函数、数据格式、服务契约或状态机 |
| 浏览器 UI 通过 | 浏览器下的布局和状态 |
| ExtendScript 通过 | 旧脚本运行通道可调用，不能代替 UXP |
| 真实 UXP 通过 | 指定 Photoshop 版本中的插件/API 实际结果 |
| 模型实测通过 | 指定 Key、模型、参数和时间的一次真实返回 |

所有测试记录有日期、版本、fixture、期望、实际、通过/失败。未运行不是通过。

## M0 第一批测试

测试素材由仓库代码生成，不依赖用户私人 PSD 或远端生图：

1. 创建独立 sRGB/RGB8 文档，放入位于非零坐标的色块层。
2. 读取精确源矩形、完整 RGBA 和 Alpha；经本地 Mock 原样回传。
3. 在同一父级正上方创建结果层，按原始坐标回写。
4. 比较 Alpha 和可见像素；完全透明位置的不可见 RGB 可归零后比较。
5. 原层保留且隐藏，新层显示；一次撤销后结果层不存在、源层可见，原始像素及其他层不变。
6. 重复透明/半透明边缘和已有非矩形选区用例，比较选区恢复。
7. 保留用户此前打开的所有文档与未保存内容；只关闭由测试本次创建且身份明确的临时文档。

有真实 UXP 报告之后，才判定 M0 通过。开发工具连接失败时保留可运行探针和明确的安装/启用步骤。

## 后续必测项

沿用初始技术设计 T01–T20 和 UI U01–U15；增加：

- 文生图不读取源图层、应用不隐藏已有图层。
- 切换到不支持编辑的模型时，整层入口不可用，文字生图入口仍可用。
- 多候选逐一预览，应用只创建一张选中结果，重复点击不重复创建。
- Midjourney 实际返回文件集合或宫格后再决定解包方式，不能只凭文档猜测。
- 公开目录、文档目录与 Key 可见性不一致时呈现准确状态。
- 字段能力冲突先保守限制，再通过实测澄清；透明度选项不可仅依据定价 UI 开放。
- 至少 20 次本地往返检查资源释放，覆盖模型晚到、断连、故障回滚、源变更和文档重开。

## 配置与公开证据

开发 Key 由用户在本机的 `.env` 或进程环境设置；示例用空值。正式设置页提交 Key 后只在本地服务内存保留，回读仅显示是否已设置。

本地报告、缓存、真实输出和账本使用 Git 忽略的 `.local/` 或 `artifacts/`。公开报告只含必要的模型 ID、参数摘要、通过状态、版本和脱敏错误。不要发布用户 PSD、签名下载链接、凭据或完整网络请求头。
